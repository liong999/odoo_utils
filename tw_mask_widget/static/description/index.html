Mask sensitive customer and personal data (Phone Numbers, Emails, Identification IDs) across Form, List / Tree, and Kanban views with granular Masking Admin role control. Built with modern OWL for Odoo 20.

Protect Customer Privacy & Meet Regulatory Compliance

In modern business operations, front-line agents and general staff often don't need full visibility into sensitive personal identifiers (PII), such as complete mobile numbers, personal email addresses, or government identity numbers. TW Mask Widget provides enterprise-grade data masking out-of-the-box, ensuring sensitive data remains concealed while maintaining a frictionless user editing experience.

Intelligent Non-Destructive Edit Behavior

1. Default View & Edit Mode

When an unauthorized user views or enters edit mode on a form, the field displays the masked representation (e.g. 08*********0) to prevent visual leakage.

2. On Field Focus / Click

When the user clicks or focuses inside the input to change the value, the input automatically clears, allowing clean typing of a new number or email.

3. Safe Blur Protection

If the user clicked by mistake and leaves the field blank before saving, the widget automatically restores and preserves the original value in the database.

Developer & XML Usage Guide

Applying the widget to your custom or standard Odoo views is as simple as adding an attribute in XML.

1. Form View Usage XML Form 
<!-- Phone / Mobile Number Masking -->
<field name="mobile" widget="mask_sensitive" options="{'mask_type': 'phone'}"/>

<!-- Work / Private Email Masking -->
<field name="email" widget="mask_sensitive" options="{'mask_type': 'email'}"/>

<!-- Identification ID / Passport / NIK Masking -->
<field name="identification_id" widget="mask_sensitive" options="{'mask_type': 'id'}"/>

<!-- Relational Many2one Field Masking -->
<field name="partner_id" widget="many2one_mask_sensitive" options="{'mask_type': 'id'}"/>
2. Tree / List View Usage XML Tree 
<list string="Contacts">
    <field name="name"/>
    <field name="phone" widget="mask_sensitive" options="{'mask_type': 'phone'}"/>
    <field name="email" widget="mask_sensitive" options="{'mask_type': 'email'}"/>
    <field name="vat" widget="mask_sensitive" options="{'mask_type': 'id'}"/>
</list>
3. Kanban View Usage XML Kanban 
<templates>
    <t t-name="card">
        <div class="d-flex flex-column">
            <strong><field name="name"/></strong>
            <div><field name="mobile" widget="mask_sensitive" options="{'mask_type': 'phone'}"/></div>
            <div><field name="email" widget="mask_sensitive" options="{'mask_type': 'email'}"/></div>
        </div>
    </t>
</templates>

Assigning "Masking Admin" Rights

By default, all standard users have masked visibility applied. To allow managers, compliance officers, or HR directors to see full unmasked values:

  1. Navigate to Settings > Users & Companies > Users.
  2. Select the user you wish to grant unmasking permissions to.
  3. Scroll to the Access Rights tab and locate the Masking category.
  4. Check the Masking Admin group.
  5. Save the user profile. The selected user will now see complete, unmasked values across all views.

Frequently Asked Questions

Does this modify raw data in the database?

No! Raw data remains 100% intact and complete in PostgreSQL. Masking is applied safely in the client interface (OWL Web Client) for unauthorized users.

What happens when a user edits a contact?

The widget smartly preserves the original value. Only if the user explicitly enters a brand-new number or email and saves will the field be updated.

Can I customize mask rules?

Yes! The module comes with pre-tuned rules for phones, emails, and IDs. You can easily extend or override the JavaScript formatting methods for custom formats.

Does it require any external third-party library?

No, zero external dependencies. It seamlessly extends Odoo 20's native OWL web client framework.
