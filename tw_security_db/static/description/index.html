TW Database Security

Restrict /web/database/manager, /web/database/selector, and all database lifecycle endpoints (Create, Duplicate, Drop, Backup, Restore) strictly to Superuser Only.

Prevent Database Exposure & Master Password Exploits

In standard Odoo deployments, database management screens (/web/database/manager and /web/database/selector) are accessible to anyone over the internet if reverse-proxy rules are misconfigured. Attackers frequently use automated scanners to brute-force the master password, dump confidential customer databases, or execute destructive drop commands.

TW Database Security seals all database management routes at the Python controller layer. Unauthenticated visitors are instantly redirected to the login screen, while standard authenticated users receive an immediate HTTP 403 Forbidden response. Only the system Superuser (OdooBot / ID 1) is permitted to access database management functions.

How the Security Verification Works

1. Session Inspection

When an HTTP or JSON request hits any database route, the controller checks request.session.uid.

2. Unauthenticated Interception

If the user is not logged in (anonymous visitor), the system redirects immediately to /web/login.

3. Superuser Authorization

If logged in, it verifies uid == SUPERUSER_ID. Only the true root superuser proceeds; all others receive HTTP 403.

Frequently Asked Questions

How do I access database manager after installing?

Simply log into your Odoo instance as the root administrator (Superuser). Once authenticated, visit /web/database/manager normally.

Can regular portal or backend users bypass this?

No. Even users with Full Accounting or System Administration groups cannot access these routes unless they are logged in with the superuser credential.

Does this conflict with Nginx or Cloudflare?

Not at all. It acts as an application-level barrier, providing defense-in-depth even if reverse proxy location blocks fail or are misconfigured.

Are automated backup scripts affected?

Standard command-line tools (e.g. pg_dump) work directly via PostgreSQL and are completely unaffected.
